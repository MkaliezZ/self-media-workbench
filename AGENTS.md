# Unified entry for AI Agents

The product is Agent-only: use the CLI/API, with no workbench frontend. Understand the user task and current project, ask only for actual missing materials, and give one clear next action. Manage commands, JSON, coordinates, models and service state yourself. Focused tasks do not require every upstream stage. Preserve originals/history, distinguish routing from execution, and separate tool success from human acceptance.

For reusable shot/motion vocabulary, discover /api/visual/shots and read references/shots.md. The pinned upstream library has 124 reference cards / 150 styles and nine executable adaptations; native_cards separately adds four original explanatory diagrams. For talking/diagram layout alternation read docs/explanatory-diagrams.md. Study editing mechanisms without inheriting a reference video's content or claims. Choose by semantic purpose, not animation count. Optional Remotion runs headlessly, uses frozen content/font/source/lock files, registers generated media after an actual completed job, then feeds the existing native timeline. No frontend, arbitrary TSX input, automatic external publishing or claims of exact upstream-demo parity. Runtime setup is explicit; ordinary workflows do not need Node. Keep technical, visual, listening and user acceptance separate.

For 打光/布光/补光 or light placement use intent=lighting and read the returned lighting.reference. Inspect the actual images, distinguish observations from assumptions, and generate/save simple, standard and ideal tiers with the lighting schemas. Registering an image alone does not establish image understanding; the calling Agent must inspect it. Exact wattage/illuminance needs matching fixture/modifier evidence. Use the source-linked tutorial policy and read docs/lighting-sources.md. Radiance/lux must not drive power selection; new plans never call Radiance. Use existing_lights for declared ceiling/practical light context and read existing_light_assessments; unknown contributions need an on/off test. Reduced operating output never automatically reduces fixture purchase wattage. Nameplate watts are declarations, not recommendations; field feedback never promotes itself to human acceptance. Preserve plan history and use fresh revision/head bindings.

For “高级口播” / advanced talking-head edits, discover talking_profiles and compile_talking_profile, then read references/advanced-talking.md. Ordinary talking-head review stays on the simple ASR/caption route. Advanced scenes compile local effect clocks to a native timeline and freeze a production_profile; inspect and save the draft, export, and verify actual voice/readability. keyframe_layer supports bounded multi-stage planar perspective, actual-pixel highlights/inversion and restrained layer finish, not 3D/tracking/matting. An existing audio stream is insufficient: actual selected intervals are checked for signal; listen to verify speech. Retain human acceptance gates explicitly requested by the user before any release/push.

This is an Agent workbench. You, the calling Agent, reason, choose topics and write content; the local service records evidence/state, validates submissions and executes media tools. No model API key or browser form is required.

Publication preparation accepts ordinary media/export bindings and native timeline/export bindings; discover publish schema and read references/publish.md. A timeline asset uses kind=timeline, timeline_plan_id and export_id. Checklist export_ids must reference completed exports also bound in assets. Technical file references never certify listening, rights or real external publication. Corrupt media import returns 422 and removes only its newly created failed copy; source files and project state remain intact. Imported video_duration/audio_duration are separate source clocks.

For any user task, use `python workbench.py run "<user task>"` (or `python3` on macOS). Pass explicitly provided files with repeated `--input` options. The entry starts a loopback service automatically, registers supported files and selects a project/start phase from actual state. You may pass `--intent` after interpreting the whole task; otherwise auto routing is a conservative hint. Do not tell the user to remember commands or provide JSON.

The returned JSON is an intake plan, **not finished generated content**. Read its context and `skill.entry`, then the reference for the selected phase. Discover submission and phase schemas via `python workbench.py schema submission` and `schema <phase>`; perform the work and submit with `python workbench.py submit <project_id> --json <your file>`. Every successful mutation requires fresh context before the next submission.

Submission `revision` must equal that fresh `context.project.revision`, not "phase version 1". Use `context_id` from the same read. `input_artifact_ids` contains upstream artifacts; source IDs belong in evidence with exact source quotes. A full workflow with all current heads returns `workflow_status=complete`, `start_at=null`, `plan=[]`: report saved results/limits and wait for a specific next task, rather than automatically starting another topic cycle. "Complete" describes saved stages, not factual verification or publication readiness.

Resume with the user's project name/ID (`--project`); ordinary follow-ups saying continue use the current session's project. If several projects match, return the candidates and request the missing choice. Never silently choose a different account. A new task can use `--new`. Session defaults to current working directory; use a stable `--session` identifier for concurrent independent chats. Current project data are outside this public checkout by default.

Inspect `start_at`, current heads, missing/stale upstreams and media jobs. A complete workflow starts at the first missing/stale phase; a focused task may start directly at script/edit/review, with an honest `standalone_reason` when required. Do not fabricate upstream artifacts just to satisfy a chain. A published-data review may remain a collection plan when data are missing. Empty metrics are null, not zero.

Every numeric metric, including a measured baseline in a planned review, needs exact source evidence and collection time. Planned targets belong in `next_experiment`/`stop_rule`, not in observed metric values. Wholly missing metrics can use null values/times and empty evidence without inventing provenance.

Media uses the actual schemas `media-import`, `media-transcribe`, `media-review`, `media-export` and routes from `call GET /api/agent/v1/capabilities`. Tasks run asynchronously; query jobs to a terminal state, preserve failed jobs, and do not say a submitted job finished. Keep original files/transcripts. Listen/inspect context before selecting pauses or full speech groups; no automatic removal of every silence/repeated token. Caption groups use the actual ASR IDs and unchanged word bounds. Export returns separate MP4/SRT/word JSON plus edit plan and provenance. Styled captions, local images and static region highlights require a saved `visual-plan` and export `visual_plan_id`; read `references/visual.md`, inspect doctor.visual_editing and real output frames. PNG/JPEG task inputs appear in project.image_assets. Changed review/run/source makes old plans stale: reconsider anchors and save a new plan. CPU composition is separate from ASR GPU strategy. No automatic online image search, tracking/matting or external publishing is provided. Product modules and descriptions use functional names without creator/account/tutorial attribution.

Industry/form editing uses editing_templates, editing-template and editing-recipe discovery. Read references/industry.md; use references/recipe-generation.md when presets do not fit. The calling Agent generates custom story/shot/pacing/audio logic. Validate, compile a source-bound draft, inspect, save unchanged and export; recipe validation is not rendering. Planning-only recipes list unsupported capabilities and must not be presented as executable. Frozen definitions preserve resume/history.

Audio-only inputs can be transcribed/reviewed. Current MP4 export requires a video source and explicitly rejects pure audio; if the authorized task includes creating visuals, retain the original audio and explicitly mark/record any generated video wrapping rather than calling it recorded footage.

`doctor` reports actual Python, executables, display-GPU vendor, ordered ASR strategy, models and optional dependencies. Read its `gpu_setup_guide` for provisioning. Auto prefers NVIDIA CUDA, Windows AMD/Intel whisper.cpp Vulkan, Apple Silicon MLX, or optional Intel Mac whisper.cpp Metal; unsupported/missing GPU components produce a retained reason before CPU fallback. `require_gpu` forbids that fallback; explicit CPU bypasses GPU attempts. The Agent handles authorized setup/model paths and resumes the saved project, without requiring human commands. Text work needs no ASR model; media needs FFmpeg/ffprobe and the ASR requirements. CT2, MLX and GGML weights are distinct. Check actual terminal backend/device/execution/fallback fields; inventory/build success is not GPU inference. Normal ASR downloads nothing. Configure process-local paths; never change global PATH or overwrite unrelated services.

Read `/api/status` and `context.skill` for actual runtime paths/hashes. Local library support is optional; no course corpus is distributed here. If a private configured ledger has `review.source_supplement`, read both the original and supplement and verify the hashes before claiming complete reading.

Keep real initial drafts, errors and revisions; use supersedes/revision_reason. 409 means refresh state and reconsider, not merely replace revision numbers. Structure-only validation is never independent truth, permission, content or market validation. Mark synthetic inputs clearly and keep unresolved production requirements as needs_review. Do not publish externally or message others without the user's actual authorization.

For silent/multiple-source/music work read references/timeline.md and discover editing_logics, timeline-plan, music-onsets, align_timeline/save_timeline/export_timeline. No ASR is needed. Register actual sources, select source-second intervals, inspect musical onset candidates and preserve meaningful silent holds. Audio beds have independent clocks; output shot edges are quantized to frames. Save against current project_revision and timeline_head using supersedes, then poll actual export jobs and inspect frames/audio. Restore by re-saving the old decisions as a new revision; never overwrite old plans/exports. The service freezes sources/maps/fonts and rejects corrupt snapshots. Native custom recipes use native_timeline mode; the ASR compiler rejects that mode. Unsupported tracking/group animation/time-warp/music generation remains planning-only.

Native timeline transitions overlap adjacent shots and reduce total duration; reviewed music targets use transition midpoints. Real rectangle/ellipse masks have source crops, static output slots, inward feather and preserved PNG alpha. Read references/timeline.md before choosing these optional fields; inspect output pixels and audio rather than treating plan validation as effect acceptance.

For document highlight/pullout/rectification/return, authored moving spotlight, image/video PiP motion, crop magnification, linear reveal or text motion, discover timeline-plan.effects and read docs/motion-effects.md. These are native source-bound components. Use actual original pixels/coordinates and output frame timing, preserve before/after/return evidence, and distinguish authored endpoint transforms from automatic OCR/tracking or arbitrary keyframe/group animation.

For video-in-text, luma/inverted track mattes and alpha foreground occlusion, use track_matte with a registered matte image plus an actual registered video/image source. Read docs/motion-effects.md, retain original alpha holes and inspect source/matte/result frames. Do not substitute automatic matting or guess that a JPEG has alpha. Text layout is preflighted before a new head or export job; keep rejection attempts and correct the plan.
