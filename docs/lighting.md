# 拍摄布光：三档方案

这是Agent执行的独立拍摄准备功能。向Agent说「按这张照片/平面图给我三档布光方案」并附图即可；不需要前端页面、专业灯光软件或模型API密钥。

## 使用

1. 把房间照片或平面图交给Agent；已有顶灯、窗光、灯具或尺寸时一并补充，不知道的留空。
2. Agent实际查看原图、记录观察和假设，保存简版/标准/理想三档，交付SVG布局、摆放原因与完整HTML报告。
3. 告诉Agent选择哪一档。它读取当前版本后保存选择；你按图试拍，反馈最明显的问题，由Agent记录一项下一步调整并按需生成新版，旧版保留。

图片登记本身不会理解房间。Agent必须区分看到的关系、用户提供的参数与待验证假设；不让使用者填写坐标或记命令。以下API细节供Agent执行和排错。

简版优先可利用窗光或已有单灯；标准增加反光/负补光控制；理想在空间允许时增加分离控制。档次不等于固定灯数或固定瓦数。空间不足时卡片保留并解释条件；当前规则面向单人固定口播，不处理多人舞台、悬挂或复杂片场。

## 数据和计算

- 原始图片保留 SHA256；跨项目或被修改的原件不能用于新方案。Agent 审图需要绑定图片的文字观察，不代表额外人工验收。
- 人物、机位、障碍和灯位共用归一化坐标，文字与 SVG 同源。已知宽深时按比例绘图；未知时仅作相对示意，不显示假精确距离。高度另行声明。
- 已有灯具可登记额定输入 W。没有具体型号/附件的测光数据时，只输出能力要求和核对方法；首版没有经校准的灯具选购数据库，不自动推荐准确瓦数。
- API 可保留同一附件、色温、距离条件下的光度资料及来源供审阅，当前不据此计算推荐电功率；不将裸灯数据用于柔光箱，不假定调光百分比线性。
- 候选灯架考虑边界、约22cm占地半径与障碍；该简化半径不能代替具体灯架、柔光箱、通道和消防检查。未知障碍高度按保守全高挡光。未模拟人体投影、墙面回光、真实配光曲线和柔光近场。
- 试拍记录是用户声明，不会自动标成效果通过。测量lux必须同时说明测量点及传感器方向。

## 教程规则与灯具选型

当前使用 `tutorial-context-v3-20261028`，不调用Radiance，也不从模拟lux反推电功率。依据包括大学CC BY 4.0摄影教材，以及经阅读核对的ARRI、神牛与爱图仕实拍教程；免费阅读的版权材料不标成开源许可。完整作者、许可、阅读状态与规则对应见[教程依据](lighting-sources.md)。

可选补充环境光（可控室内／混合窗光／强日光）、主光方式（柔光箱／反射）和最宽景别。规划先看环境与背景曝光，再选择光源面积、附件和输出余量；三档不机械对应三个W值。强日光分支提示先控窗光，再核对高输出灯具案例，未知环境不默认低瓦数。

灯具登记的输入W只是资产资料。报告另列选型依据和试拍检查；案例中的600–700W级也不是保证或通用最小值。照度数据继续可保存，但当前不参与自动选瓦数，不输出虚假的调光百分比。历史Radiance适配器仅供开发诊断，旧配置不再开启产品规划计算。

## Agent/API

### 随平面图补充顶灯上下文

告诉Agent房间里是否有顶灯、拍摄时是否开启，以及已知灯种、功率/色温或试拍观察。Agent通过 `scene.existing_lights` 登记已有光源；投影位置不是灯架占地。仅凭照片不能确认灯种或色温时，保持未知，或明确标为情景假设。

结果新增「已有光源能否减少主光？」评估：未对照则待验证；有用面部补光可能减少主灯工作输出；仅照背景不能抵扣人脸主光；不利阴影或混色优先控制/关闭；计划关闭的不计入。已有灯W不能与主灯W相减，有用补光也不等于可以购买更低额定功率的主灯。已知效果必须填写观察依据，仍是声明，不自动变成人工验收通过。

先固定机位、快门、光圈、ISO和白平衡，主灯关闭，拍顶灯关/开两版；看面部曝光、阴影和肤色，再加入主灯逐步调整。未知色温不按“白炽灯”自动填写2700K/3200K，不输出凭空的瓦数或调光减幅。

[顶灯上下文验收](../evaluation/lighting-context-20261028.md)包含15㎡坐播模拟示例，未冒充真实灯具或采购验证。

统一入口 `python workbench.py run "按照片给三档打光方案" --input /absolute/path/room.png --intent lighting`，随后按返回的布光说明实际执行。详见 [Agent 布光流程](../skills/self-media-workflow/references/lighting.md)。

| 接口 | 用途 |
|---|---|
| `GET /api/lighting/status` | 能力与可选引擎状态 |
| `POST /api/projects/{pid}/lighting/images?name=room.png` | 原始图片字节上传 |
| `POST /api/projects/{pid}/lighting/plans` | 校验场景，保存恰好三档与布局 |
| `GET /api/projects/{pid}/lighting/plans` | 版本、当前方案与选择 |
| `GET /api/projects/{pid}/lighting/plans/{id}` | 读取历史结构化方案 |
| `GET .../{id}/files/{simple.svg,standard.svg,ideal.svg,plan.json,report.html}` | 导出 |
| `POST .../{id}/select` | 选择当前方案的一档 |
| `POST .../{id}/field-checks` | 保存试拍声明 |

写操作带项目修订号；新方案需引用 `supersedes`；相同 `request_id` 和内容可幂等重放。Agent context 返回图片、版本、选择和反馈。场景/生成/选择/反馈 schema 可从 `/api/agent/v1/schemas/lighting-*` 读取。开发依据见 [规划与选型](plans/lighting-planner.md)，本次技术验收见 [记录](../evaluation/lighting-20261028.md)。真实房间、新手照图执行和换人复做仍待验证。

当前教程规则迭代验收见[记录](../evaluation/lighting-tutorial-rules-20261028.md)；初版Radiance数学记录仅作为历史证据。
