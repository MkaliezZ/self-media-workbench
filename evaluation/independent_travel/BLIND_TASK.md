# 独立盲测任务（素材先于待验 commit 制作）

本任务只使用 materials 中独立生成的四个旅行片段和一条原创节拍音乐。均为自制插画动画与合成声音，不是真实拍摄，不含旁白，不使用付费或第三方素材。不得导入主仓库现有 fixture、样片或预制 timeline。

## 给执行 Agent 的任务

从四个片段剪一条 16 秒的横屏 1280×720、30 fps 旅行短片，表达乘车进山、沿步道指引、登顶、返程的关系。使用四个不同源，使用原有音乐节拍，不加配音或字幕。画面保留完整比例，允许黑边，不能裁掉源画面关键文字。主音乐使用提供的原创 120 BPM 音轨；A、C 保留少量原声，B、D 没有原声时仍应正常使用。

依照公开 README、AGENTS、skill 与 schema 完成：注册材料 → 创建纯画面/多源/音乐驱动方案 → 编译/保存时间轴 → 实际导出 → 观看并核对输出。首先记录第一次尝试，不得覆盖失败记录；计划合法且渲染成功后，进行一次局部剪切、一次撤销/恢复、过期计划或旧上下文保护检查，并重新导出。全程无需识别或伪造旁白。

剪辑需保留 B 源 2.5–5.5 秒中可读的 SUMMIT 指路牌至少 1 秒。无声不意味着无意义。四段顺序固定为 A → B → C → D。成片段落时长分别为 3、4、5、4 秒；所有片段边界应落在音乐 0.5 秒间隔的节拍上。采用源区间 A 1.25–4.25 秒、B 2–6 秒、C 1–6 秒、D 0.5–4.5 秒。不得整体改变素材播放速度。音乐从 0 秒起、与成片同长，结尾可短淡出。

剪切/恢复检查：基于首次成功方案，从 B 中去掉源 4–5 秒，再恢复该秒。剪切版时长 15 秒，恢复版回到 16 秒；所有保留下来的源时间连续对应。恢复后应出现指路牌，并保持后续源起止点与恢复前一致。应通过当前产品提供的编辑路径完成，不能直接用外部 ffmpeg 代替工作台导出。

## 独立验收依据

1. 检查真实 MP4 的 ffprobe、视频帧与音频波形；API 的 success/done 只作过程证据。
2. 允许输出时长误差不超过一帧（1/30 秒），第一版和恢复版目标 16 秒；剪切版目标 15 秒。音画轨必须存在，且无解码错误。
3. 在片段边界前后与每秒提帧，凭底部源字母/源时间标记核对多源顺序及裁切范围。源时间误差允许一帧，源素材小数帧率可追加量化误差一帧。不能有错源、画面拉伸或意外黑帧。
4. 3、7、12 秒的画面切换应与原始音乐节拍同位；音乐不能被逐源重新开始、拼接或错位。提取成片 PCM 与音乐源做相关对齐，允许 AAC 编解码误差，累计漂移不超过一帧。
5. B 无音频轨但有关键画面，不能因无旁白而漏掉。A、C 原声按计划混合；B、D 不得触发缺音轨失败。
6. 首次、剪切、恢复三版分别保存；剪切/恢复后旧方案应拒绝或明确要求重新核对，不得静默使用过期依赖。以实际 schema 的版本机制为准。
7. 另试错误源 ID、超出源时长、节拍越界/不合法时间轴；应在导出前得到可理解的失败，且不破坏既有成功成片。具体字段只从待验版本公开 schema 发现。
8. 记录实现边界。Windows 和 macOS 的“实际运行”要分别有主机/系统、commit、命令、终态作业、ffprobe 及验片证据；仅模拟平台路径、CI 配置或单元测试不算 macOS 实跑。

## 证据纪律

- `attempts/001-first-attempt` 必须保留输入、首次计划/命令、原始响应、终态日志和真实失败，即使之后修好。
- 每次失败写明触发、预期、实际、最小复现、修改位置、重试证据；不回写第一轮记录。
- 缺能力、无可用 macOS 主机或不能实际播放的环节标为 NOT_TESTED/BLOCKED，不能用推测通过。
- 本目录不修改主仓库代码。收到指定 commit 后才全新克隆，克隆后仅按公开说明发现用法；不从主 Agent 获得成片或预期答案。
