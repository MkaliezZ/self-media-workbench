# Script and timing

Keep the selected problem and promised outcome stable. Choose a structure from actual material: result→steps, problem→demonstration, qualified viewpoint→evidence, recorded experience→transferable limit, or controlled comparison. No fabricated obstacle, injury, dialogue or personal history to fill a structure.

Each segment records start/end, spoken text, available visual, subtitle and claim IDs. Use concrete language without adding unsupported numbers. Distinguish a reconstructed/illustrated scene from evidence of a real event. One main action should be executable and any promised download/link must exist.

For an estimate use 240–300 counted characters/minute as an explicit production assumption, plus actual demonstration pauses. Run scripts/script_check.py on final segments; inspect each segment and total. Numeric and English reading may differ from character counts. Estimates/TTS are not human read-aloud tests. Revising wording must not quietly change the topic or turn an example into personal experience.
