# Local visual editing

Use for cue emphasis, local image placement or static region highlights. Continue the existing media project through the unified entry; PNG/JPEG inputs are copied into project.image_assets. No external image service, remote model, tracking, matting, music generation or automatic publishing is provided.

1. Read current context, actual review and capabilities. Check `visual_status` (also doctor.visual_editing); follow visual_setup_guide for missing filters/font. Resolve missing dependencies before promising a styled export. CPU composition is independent of ASR acceleration.
2. Inspect the real source frames/audio and user goal. Select an image only if it adds evidence or explanation. An illustration must not impersonate a particular event/person. If essential material is absent, record the gap and continue what is possible. Do not add an image merely because a sentence exists.
3. Review subtitles and save explicit `caption_groups` covering retained ASR IDs exactly once in order. Correct text is not character alignment. Keep negatives, qualifications, units and meaningful demonstration holds. For emphasis, select whole reviewed caption groups; do not invent character timings or silently split one ASR group.
4. Discover `schema visual-plan`. Bind current project_revision, review_revision, asr_run and source_sha256. Select consecutive retained word_ids with a reason for each event. Image `slot` is a normalized destination rectangle; contain-fit preserves the entire picture. Optional `highlight` uses normalized original-image coordinates. `regions.rect` uses normalized source-video coordinates. These are static rectangles, not tracking.
5. Use real absolute local PNG/JPEG paths, matching hashes, image nature and nonblank source_note/usage_scope. The service freezes images/font. Captions can be disabled for image/region-only exports. Default captions are white; selected cues are larger and gold. No-op plans and invalid anchors are rejected. Save via the discovered visual_plan_save route, keeping request_id stable only for an identical retry.
6. Refresh context after saving. Export with `media-export` including visual_plan_id and the current review binding. Poll to terminal done; failed jobs and all attempts remain. `visual.mp4` is the styled output; ordinary reviewed_cut.mp4, separate SRT, word JSON, mapping, visual plan/timeline and provenance remain available. Existing exports and originals are not replaced.
7. Inspect decoded representative frames before/during/after events, image relevance, face/UI/caption overlap, readable text, layout and audio synchronization. Decode the whole file and compare original hashes. Rendering success does not establish semantic quality or performance improvement.
8. A new ASR run, cut, restoration or text/group revision makes prior visual plans stale. Refresh the actual review, reconsider every affected anchor and save a new plan; never just replace version numbers. Output time is recomputed from retained source intervals. Old plans/exports remain for comparison. Resuming a project returns visual_plans with stale flags; do not automatically choose an arbitrary latest plan.

Use functional names for product modules and outputs. Operational image provenance and usage declarations belong in private project records.
